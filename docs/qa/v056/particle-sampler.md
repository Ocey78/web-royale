# Source billboard particle sampling

The renderer now samples all ten retained `MovieClipEmitterData` records. The previous sampler omitted both Dark Prince Hero smoke emitters because they contain `SpawnCone`, `SpawnLocation`, and `Deceleration`, and omitted Berserker Hero transform sparks because their alpha is a packed `_b0` curve.

The source records are copied unchanged from the client SCDB. Six regression fixtures in `tests/fixtures/source-particles-v056.json` include their original record SHA-256. The graph expansion did not add new particle component classes. The actual retained classes are `SpawnBurst`, `SpawnRate`, `SpawnPlanar`, `SpawnCone`, `SpawnLocation`, and `Deceleration`.

`src/source-particles.js` keeps the existing sampling contract: record, absolute effect age, presentation seed, and quality budget. It returns original movieclip references, source positions, size, alpha, color, and rotation. Extra output fields expose independent X/Y stretch, movieclip looping, render blend mode, and the authored follow-emitter flag to the renderer. This module does not write to source records, units, animation clocks, replay state, or global randomness.

Implemented source formats include scalar constants; two-endpoint scalar/vector curves; six-entry cubic curves; packed `_b0` scalar keys and component-wise X/Y curves; and `_l0` linear color stops. Emission respects source delays, zero burst counts, timed bursts, finite/infinite rates, and finite-emitter restart windows. Particle lifetime accounts for source curve extrema rather than assuming the final key is the largest value. Sample ordering follows birth time, then source component/burst order.

Bounds are 48 returned particles, 384 candidate births, 64 components, 256 keys/bursts, and at most 64 integration steps per particle. The caller can set a smaller budget, including zero. Infinite emitters seek directly to their recent birth window, so very large absolute presentation clocks do not replay every prior birth.

## Particle dimensions and birth transforms

The original `vmc_gen_smoke_01` outline is 75 SC pixels wide. The Dark Prince emitter multiplies it by `globalScale=.1` and a size curve around `.18–.25`, yielding roughly 1.35–1.875 model units before jitter. The renderer projected emitter positions at 32 canvas pixels per model unit but previously omitted that conversion from particle dimensions. A source-only diagnostic with particle dimensions multiplied by 32 produces compact blue-gray puffs roughly comparable to the actor's body width, consistent with the native preview. The uncorrected puffs were only a few pixels wide in the enlarged diagnostic. This comparison supports the model-to-canvas unit conversion; it does not prove exact native dynamics. The factor applies to sampled particles only. Direct `5008` movieclips have no emitter `globalScale` and need their own authored convention.

`ParticleTransformHistory` in `source-particles.js` stores copied renderer-provided position, quaternion, scale, canvas origin and outer actor factor for each stable unit/emitter key. A birth between observations uses linear translation/scale/origin interpolation and shortest-arc quaternion interpolation. A following emitter resolves the current pose; a detached emitter resolves the pose at current time minus particle age. The renderer can then compose the birth matrix and compensate the canvas-origin difference. New activation keys and clock rewinds reset an emitter. The helper is independent of THREE and gameplay clocks. Defaults cap storage at 128 emitters, 64 poses per emitter and a four-second observation window; the renderer must prune expired entries.

Five dedicated regression tests failed before the helper existed and now pass, alongside the ten particle-sampler checks. They cover the actual non-following Dark Prince source record, retained birth transforms after movement, intermediate births and rotations, opposing quaternion signs, copied inputs and outputs, invalid-input rejection, rewind, activation changes, duplicate observations, age pruning and hard memory limits. Births before the first observed pose deliberately use that earliest pose: prior movement cannot be recovered without earlier presentation history.

The final integrated GPU run passes 224 actor/state/team/time samples. This verifies that older puffs stay behind the moving actor. The comparison is saved in `effects/source-charge-moving/history-comparison.json`; it does not establish exact native trajectories. All three final runs have clean browser/asset/shader logs, unchanged entity objects and no diagnostic-canvas edge pixels.

## Fidelity limits

These are source-authored data evaluated by a bounded browser sampler, not a claim of bit-identical native particle simulation. Prior inspection of the protected/stripped client `libg.so` found no gameplay symbols or readable gameplay strings; native dynamics could not be independently recovered. The source assets establish the values and curve key layout. Handle interpolation, uniform cone/spawn-region sampling, a fixed seeded rate jitter, fixed-step curved deceleration, and finite emitter restart timing are browser interpretations. The source-native preview of Dark Prince confirms distinct blue-gray smoke but is not numerical trajectory validation.

The retained records do not require `Drag`, `Ground`, `CurlNoise`, or `TangentVelocity`. Those components elsewhere in the larger client database are not implemented and must not be represented as exact support. Source gradient/trail fields are also outside this sampler. The actual Dark Prince smoke records omit `followEmitter` (the default false), while Berserker sparks explicitly set it true. The drawing layer now composes detached particles through their observed birth pose and follows the current pose for attached particles. This history interpolates observed display poses; it cannot reconstruct movement before observation or beyond the bounded retained window. Direct `5008` movieclip scale, source blend-mode enum equivalence, and exact native spawn/deceleration integration remain unverified. Mesh effects and material timelines are handled separately.
