# UI sharpness and layout implementation plan

**Goal:** Retain the original visual style, full offline game, closer camera and actual emotes while eliminating distorted label painting, stretched controls and overlapping menu content.
**Architecture:** Existing DOM controls remain the interaction and accessibility layer. Rendered original glyphs supply titles and labels. A focused UI layout pass fits text uniformly, re-rasterizes on scale changes and preserves artwork aspect ratios. Original button corners use nine-slice rather than full-image distortion.
**Tech stack:** Plain JavaScript, Canvas 2D, CSS, Node test runner, packaged Chromium tests.
**Spec:** User request in this conversation; no approvals requested.

## Global constraints
- Do not change battle mechanics, XP, rewards, shop intervals or player saves.
- Preserve the 540x960 logical viewport and camera {x:30,y:110,scale:1} from the last requested zoom.
- Keep actual archived emote timelines; do not replace animations with CSS bobbing.
- Do not distribute font binaries. Use existing original raster glyph atlas and local assets only.
- Full source + dist + offline launcher ZIP, not a patch.

## Review focus
- Maximum resources and 24-character player names must fit their dedicated regions.
- Long card names, magic items, modal descriptions and input labels wrap or fit uniformly.
- Physical canvas resolution must cover the displayed pixel size at DPR 1/2/3 and viewport resize.
- Repeated hydration cannot create nested wrappers or endlessly increase canvas count.
- Changing collection tab, shop hour, deck, modal or pause state must preserve working controls.
