# Historical air routing: primary evidence and limits

The supplied APK's table data supports a distinction between flight and direct-path flight, and contains explicit lane/default-target controls. It does not expose the native routine that combines those controls. This note records evidence, not a claim of recovered native behavior.

## Primary public statement

Supercell's [April Update, published 31 March 2025](https://supercell.com/en/games/clashroyale/blog/release-notes/april-update/) states that historical troops first moved horizontally to their lane before advancing; the update reduced lane reliance and introduced more diagonal movement. This confirms historical lane-directed movement in general. The statement does not separately specify Baby Dragon or all air troops.

## Original table values

The raw source entries were read from the supplied `com.supercell.clashroyale-3.5.0-APK4Fun.com.apk`. Compressed-entry hashes and decoded-file hashes are in `air-routing-evidence.json`; original unpacked CSV bytes are preserved under `source/`.

- `BabyDragon`: FlyingHeight 3500, SightRange 5500, Range 3500, Speed 90, CollisionRadius 500, AttacksGround true, AttacksAir true. FlyDirectPaths, SightClip and SightClipSide are blank.
- `SkeletonBalloon` is the only row in characters.csv with FlyDirectPaths explicitly true. Ordinary flyers leave it blank. A blank value is not independent proof of the runtime's boolean default.
- `LOGIC_DEFAULT_TARGET_USE_LANE_ID`: true.
- `LOGIC_LANE_ID_BASED_DEPLOY_SEQUENCE`: true.
- `LOGIC_PATHFIND_BACKWARDS_TRY_KEEP_TARGET`: true.
- `LOGIC_PRINCESS_TOWERS_ALWAYS_AS DEFAULT_TARGET`: true. The space in this key is literal.
- `LOGIC_XPOS_BASED_TOWER_TARGETING`: true.
- `EXTRA_SIGHT_RANGE_TO_CROWN_TOWERS`: 2000; ordinary-building extension: 0.
- `LOGIC_RANGE_EXTENSION_TO_KEEP_TARGET`: 25.

These are verified flags and values. Their precise ordering, distance metrics, fallback rules after a tower dies, and waypoint algorithm remain unknown. The supplied APK has no `.so` entry, so its native battle implementation is not available here as a libg.so.

## Practical implication and remaining uncertainty

The v0.30 navigator's unconditional `air => straight-line segment` merged default advancement with chasing an acquired target. That is a concrete implementation simplification, whereas the source distinguishes flying height, direct-path flight and lane-based defaults. Source evidence supports investigating those as separate behaviors. It does not justify converting every flyer into a ground mover or forcing every aerial pursuit through a bridge.

To claim a specific historical Baby Dragon route, a controlled native gameplay reference is still needed: empty-board deployment behind King/Princess, own-lane Princess removed, and defense followed by resumed advancement, mirrored for both sides. Native ordering of King versus surviving opposite-lane Princess is not proven by the flag names alone.
